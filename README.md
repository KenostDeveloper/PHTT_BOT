# PHTT BOT

Бот следит за страницей [phtt.ru/raspisanie_zanyatiy](https://phtt.ru/raspisanie_zanyatiy/)
и, как только там появляется новое расписание, публикует его картинками
в каналы корпусов.

## Запуск

```bash
npm install
cp .env.example .env   # заполнить BOT_TOKEN и CHAT_ID_CORPUS_*
npm start
```

Нужен установленный **poppler** (`pdftocairo`, `pdftoppm`, `pdfinfo`):

```bash
sudo apt install poppler-utils   # Debian/Ubuntu
brew install poppler             # macOS
```

Разовая проверка без запуска сервиса:

```bash
npm run once
```

## Что где лежит

| Файл | Назначение |
| --- | --- |
| `main.js` | планировщик, обход корпусов, `/health` |
| `lib/config.js` | чтение `.env`, список корпусов, автопоиск poppler |
| `lib/site.js` | разбор таблицы расписаний на сайте |
| `lib/pdf.js` | загрузка PDF и хеширование |
| `lib/images.js` | обрезка полей и отрисовка страниц в PNG |
| `lib/state.js` | история отправленного (хеши) |
| `lib/telegram.js` | подпись и отправка с повторами |

## Как получается качество картинок

1. Страница отрисовывается в маленький серый растр (`PROBE_DPI`), по нему
   находятся реальные границы содержимого — поля и пустой низ листа
   отбрасываются.
2. Найденная область рендерится из PDF **сразу** в нужном разрешении
   (`IMAGE_WIDTH`, по умолчанию 2560 px по ширине). Промежуточного
   масштабирования нет, поэтому текст остаётся резким.
3. Размеры проверяются по ограничениям Telegram (сумма сторон, соотношение
   сторон, вес файла) и при необходимости уменьшаются.

Все три корпуса отправляются картинками: одна страница PDF — одно фото,
несколько страниц уходят альбомом.

## Настройки

Все параметры — в `.env`, см. `.env.example`. Основные:

- `BOT_TOKEN`, `CHAT_ID_CORPUS_1..3` — доступы и каналы;
- `IMAGE_WIDTH` — ширина картинок (2560 — максимум, который Telegram хранит);
- `CHECK_CRON` — как часто проверять сайт;
- `SEND_ON_FIRST_RUN` — рассылать ли всё при первом запуске (по умолчанию нет);
- `POPPLER_PATH` — путь к бинарникам, если автопоиск не сработал.

## Поведение

- Каждое расписание (левая и правая ячейка таблицы) отслеживается отдельно —
  если обновились оба, придут оба сообщения.
- Хеш сохраняется только после успешной отправки: при сбое Telegram расписание
  уйдёт на следующей проверке, а не потеряется.
- Битые ссылки (404 на сайте) не повторяются и не роняют остальные корпуса.
- Прошлые версии хранили PDF целиком в base64 (`info/*.txt`) — при первом
  запуске они автоматически переводятся в хеши, повторной рассылки не будет.
